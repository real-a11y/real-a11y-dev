  paragraph "Heading levels create a hierarchy — like an outline in a word processor:"
  list

    text "The level number indicates depth, not visual size. CSS controls how big headings look — the HTML level controls what they"

  paragraph

  heading "What to check" (level 2)
  heading "Exactly one H1" (level 3)
  paragraph
    text "Every page should have exactly one"
    code "<h1>"
    text "— the page title. Zero means there's no top-level label. More than one means the page has multiple "titles" and the hierarchy has no single root."
  button "Copy Code"
  code "H1 "Our Products" H1 "About Us" ← two H1s — which is the page title?"
  paragraph
    strong "The fix:"
    text "Keep one"
    code "<h1>"
    text "for the page title. Demote the other to"
    code "<h2>"
    text "or restructure the page."
  heading "No skipped levels" (level 3)
  paragraph
    text "Heading levels should only increase by one at a time. Jumping from"
    code "<h1>"
    text "to"
    code "<h3>"
    text "breaks the outline — screen reader users navigating by heading level lose their place in the hierarchy."
  button "Copy Code"
  code "H1 "Dashboard" H3 "Recent Activity" ← skipped H2"
  paragraph
    strong "The fix:"
    text "Insert the missing level, or demote the deeper heading. In this case, either add an"
    code "<h2>"
    text "section above "Recent Activity" or make it an"
    code "<h2>"
    text "."
  heading "Headings that aren't headings" (level 3)
  paragraph
    text "Sometimes developers use"
    code "<h3>"
    text "or"
    code "<h4>"
    text "to get a specific font size, not to create structure. The Headings view will reveal this — you'll see headings that don't belong in the outline."
  button "Copy Code"
  code "H1 "Settings" H2 "Account" H4 "Note: changes take 24 hours" ← not a real section H2 "Privacy""
  paragraph
    strong "The fix:"
    text "Use CSS to style the text at the size you want. Don't pick a heading level based on how it looks — pick it based on where it falls in the outline."
  heading "Missing headings" (level 3)
  paragraph "If a major section of the page has no heading, screen reader users can't jump to it. They have to arrow through every element sequentially to find it."
  paragraph "Compare the Headings view to the visual layout. Every distinct section a sighted user would recognize should have a heading in the outline."
  heading "Headings inside interactive elements" (level 3)
  paragraph
    text "A heading inside a"
    code "<button>"
    text "or"
    code "<a>"
    text "creates confusing behavior — the element shows up both in heading navigation and interactive navigation, and screen readers may announce it inconsistently."
  button "Copy Code"
  code "H2 "Click here to expand" ← heading inside a button"
  paragraph
    strong "The fix:"
    text "Remove the heading from inside the interactive element. Use"
    code "aria-label"
    text "or visible text instead."
