  heading "@real-a11y-dev/mcp" (level 1)
  paragraph "Beta — preview page"
  paragraph
    text "Published on npm as a"
    strong "beta"
    text ": the API and tool surface may still change before 1.0, and audit fidelity is bounded by known engine issues. Pin a version rather than tracking the latest tag if you build on it."
  paragraph
    text "The Real A11y MCP server gives an AI assistant a real browser and the accessibility tree behind any page, so it can"
    strong "audit"
    text "a URL and report the defects a screen reader would announce — not guess from pasted HTML (which hides computed roles and visibility) or a screenshot (which has no semantics). Point any"
    link "Model Context Protocol"
    text "client at it and ask it to audit a page in plain language."
  paragraph
    text "Accessibility is a property of the"
    strong "rendered"
    text "page — the roles, names, and visibility a browser actually computes, not what's in the HTML source. So the server drives a real browser (via Playwright) rather than parsing markup. You need:"
  list
    listitem
      strong "Node.js 20+"
      text "— the server runs under Node and is fetched with"
      code "npx"
      text "."
    listitem
      strong "A Chrome binary"
      text "— install one with"
      code "npx -y @real-a11y-dev/cli install"
      text ", which downloads"
      link "Chrome for Testing"
      text "and, being the CLI's installer, needs Node.js 22.12+;"
      code "npx playwright install chromium"
      text "also works."
    listitem
      strong "An MCP client"
      text "— Claude Code, Claude Desktop, Cursor, VS Code, Windsurf, or any other MCP-capable tool."

  heading "Auditing a page behind a login" (level 2)
  paragraph "To audit a page only a logged-in user can see, save a browser session once, then point the server at it — the assistant never touches credentials."
  list
    listitem
      paragraph
        strong "Save a session"
        text "with the CLI's login helper (a one-time human step):"
      button "Copy Code"
      code "npx -y @real-a11y-dev/cli login https://app.example.com --save auth.json"
      paragraph
        text "A real browser opens; sign in by hand (passwords, SSO, MFA, and passkeys all work), then press Enter. Playwright's storage state — cookies and origin storage — is written to"
        code "auth.json"
        text ". Keep that file out of version control; it holds live session tokens."
    listitem
      paragraph
        strong "Point the server at it"
        text "with two environment variables in your MCP config:"
      button "Copy Code"
      code "{ "mcpServers": { "real-a11y": { "command": "npx", "args": ["-y", "@real-a11y-dev/mcp"], "env": { "REAL_A11Y_MCP_STORAGE_STATE": "/absolute/path/to/auth.json", "REAL_A11Y_MCP_ALLOWED_ORIGINS": "https://app.example.com" } } } }"
    listitem
      paragraph
        strong "Audit as usual."
        text "Every page now opens already authenticated, and"
        code "open_page"
        text "tells the assistant the session is active so it won't try to log in."
        code "REAL_A11Y_MCP_ALLOWED_ORIGINS"
        text "pins auditing to that origin, so a redirect can't route your session to another site."
  paragraph
    text "The session path is server configuration, never a tool argument, so tokens stay out of the assistant's context. See"
    link "Authenticated pages"
    text "for the full workflow and security rules."

  heading "How it compares to Playwright MCP" (level 2)
  paragraph
    text "This"
    strong "complements"
    text "a browser-automation MCP such as"
    link "Playwright MCP"
    text "— it doesn't try to replace it. Both can act on a page now, but they act for different reasons:"
  list
    listitem
      strong "Playwright MCP"
      text "drives a page for"
      emphasis "automation breadth"
      text "— arbitrary selectors, hover, drag, file uploads, multiple tabs — using the accessibility snapshot as a means to act."
    listitem
      strong "Real A11y"
      text "acts"
      strong "through the accessibility tree and judges what changed"
      text ". Its"
      link "act tools"
      text "target"
      strong "role + accessible name only"
      text "— a control the tools can't reach is itself an accessibility smell — and every action pairs with"
      link "diff_tree"
        code "diff_tree"
      text "'s answer to"
      emphasis ""what did that change for a screen reader?""
      text ". Its audit reports what assistive technology would announce as"
      emphasis "broken"
      text "."
  paragraph "For an accessibility flow — open the dialog, judge the dialog — Real A11y now stands alone. For automation verbs it doesn't ship (hover, drag, uploads, multi-tab), pair the two: drive with Playwright MCP, judge with Real A11y."
  paragraph "Two different "Playwrights""
  paragraph
    text "This package is"
    emphasis "built on"
    strong "Playwright the library"
    text "— the browser driver it takes as a peer dependency, which npm installs with it. It"
    emphasis "complements"
    strong "Playwright MCP"
    text ", the automation server above. Same underlying engine, different jobs."
  heading "Limitations" (level 2)
  list
    listitem
      strong "Scope."
      text "It runs seven rules today — unlabeled interactive elements, form controls labeled only by"
      code "title"
      text "/"
      code "aria-describedby"
      text ", images missing alt text, heading order, dialog labeling, landmark structure, and controls that share an accessible name — plus the full semantic tree. It is not a complete WCAG or axe-core suite; it is semantic-tree-based and tuned to "what a screen reader announces," with"
      code "label-title-only"
      text "and"
      code "unique-interactive-names"
      text "as its best-practice extras. For contrast, focus visibility, and other rendered/interactive checks, pair it with"
      link "axe-core"
      text "and manual testing."
    listitem
      strong "Fidelity follows the engine."
      text "The tree is a reimplementation of accessible-name / role computation, not the browser's native accessibility tree. It is tuned to match what assistive tech announces, but can diverge on edge cases."
    listitem
      strong "Requires a real browser."
      text "The assistant's environment must be able to launch Chromium or connect to one over CDP."
