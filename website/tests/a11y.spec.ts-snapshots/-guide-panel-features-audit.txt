  heading "Dialog auto-scope" (level 3)
  paragraph "When the page opens a with , the tree re-roots to that dialog: the dialog becomes the root row, and the page behind it drops out. This is what a screen reader user effectively gets. The browser makes the rest of the page inert, and the dialog is the only thing they can navigate."
    code "<dialog>"
    code "showModal()"
  paragraph "It does this wherever the dialog is on the page, including outside the element an in-page panel is scoped to, and it re-roots back when the dialog closes or is removed. The exception is shadow DOM: a dialog inside a shadow root doesn't re-root the tree, and no dialog re-roots a panel whose root is inside a shadow root."
  paragraph "Only a modal does this. A opened with , or an element with or , does not re-root the tree, and the page stays in the tree around it. If one of these is outside an in-page panel's root, it joins the tree only when it has a of or , which widens the tree to the whole page. A plain opened with there stays out of the tree. Dialog libraries such as Radix, MUI and Headless UI hide the rest of the page with or , so that content drops out of the tree too. The tree then shows the dialog alone, but its root is still the page, not the dialog, so the extension shows no bar for it."

  heading "Why the in-page surfaces default to off" (level 3)
  paragraph "If activating a tree row stole focus to the host element, every Enter / Space on a row would yank focus out of the panel and break tree-pattern keyboard navigation. Same for scroll — every arrow-key step would scroll the page out from under you. The extension and Storybook addon don't have that problem because the panel and the inspected DOM live in different windows / iframes; on a host element in one document can't pull focus out of a panel in another."
    code ".focus()"
  paragraph "The broader principle, recorded in the changelog when these defaults were established:"
    emphasis "opt-in host-app side effects so audits and test harnesses don't disturb the app under test."
