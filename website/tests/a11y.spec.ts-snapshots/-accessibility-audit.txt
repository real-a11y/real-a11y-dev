  heading "Accessibility Statement" (level 1)
  paragraph
    emphasis "Last updated: 2026-07-29"
  paragraph "Real A11y builds accessibility tooling. Holding our own website, docs, and products to the same standard is table stakes — and also the best dogfood there is."
  heading "Standards we target" (level 2)
  list
    listitem
      strong "Web Content Accessibility Guidelines (WCAG) 2.2, level AA"
      text "for the website and all product UI (Chrome extension side panel, Storybook addon panel, Inspector embed)."
    listitem
      strong "WAI-ARIA Authoring Practices"
      text "for all interactive patterns (tree view, toolbar, listbox, dialog)."
    listitem
      strong "Keyboard operability"
      text "for every interactive surface. Nothing is mouse-only."
  paragraph "The accessibility tree the tools surface is built on top of the same HTML/ARIA semantics we expect our own surfaces to follow."
  heading "Known gaps" (level 2)
  list
    listitem
      text "The tree view in the Chrome extension uses the WAI-ARIA"
      code "tree"
      text "pattern. On very large pages (10K+ elements) the virtualization gap can cause noticeable delay for screen-reader users. Tracked as an open issue."
    listitem "The "Curtain" mode (hide page visuals to audit purely from the tree) intentionally hides page content; this is a feature, not a regression, but it is incompatible with external screen-reader workflows that rely on sighted co-operation."
    listitem "The Storybook addon panel inherits whatever theme Storybook provides; contrast on custom Storybook themes is the theme author's responsibility."
  heading "How we test" (level 2)
  list
    listitem
      text "Automated:"
      code "@real-a11y-dev/testing"
      text "assertions ("
      code "assertNoUnlabeledInteractive"
      text ","
      code "assertHeadingOrder"
      text ","
      code "assertDialogsLabeled"
      text ","
      code "assertLandmarkStructure"
      text ") run in CI on every PR, alongside axe on every route in both themes."
    listitem
      text "Automated:"
      strong "and separately, through Chromium's own accessibility tree"
      text "— every route of this site, audited by our own CLI on every PR. Both checks above compute the tree"
      emphasis "in the page"
      text "; the browser computes a stricter one, and where they disagree the browser is what assistive tech gets. That gap once let three unlabeled links ship on this site's home page past a green run, so it is now its own gate rather than a thing we rely on noticing."
    listitem "Automated: a11y tree diff bot comments on PRs when the extracted tree for fixture pages changes in any measurable way."
    listitem "Manual: keyboard-only walkthrough of the website and extension side panel before every release."
    listitem "Manual: NVDA + Firefox, VoiceOver + Safari, JAWS + Chrome for major features before release."
