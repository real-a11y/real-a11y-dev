  heading "Accessibility Statement" (level 1)
  paragraph
    emphasis "Last updated: 2026-07-29"
  paragraph "Real A11y builds accessibility tooling. Holding our own website, docs, and products to the same standard is table stakes — and also the best dogfood there is."
  heading "Standards we target" (level 2)
  list
    listitem "for the website and all product UI (Chrome extension side panel, Storybook addon panel, Inspector embed)."
      strong "Web Content Accessibility Guidelines (WCAG) 2.2, level AA"
    listitem "for all interactive patterns (tree view, toolbar, listbox, dialog)."
      strong "WAI-ARIA Authoring Practices"
    listitem "for every interactive surface. Nothing is mouse-only."
      strong "Keyboard operability"
  paragraph "The accessibility tree the tools surface is built on top of the same HTML/ARIA semantics we expect our own surfaces to follow."
  heading "Known gaps" (level 2)
  list
    listitem "The tree view in the Chrome extension uses the WAI-ARIA pattern. On very large pages (10K+ elements) the virtualization gap can cause noticeable delay for screen-reader users. Tracked as an open issue."
      code "tree"
    listitem "The "Curtain" mode (hide page visuals to audit purely from the tree) intentionally hides page content; this is a feature, not a regression, but it is incompatible with external screen-reader workflows that rely on sighted co-operation."
    listitem "The Storybook addon panel inherits whatever theme Storybook provides; contrast on custom Storybook themes is the theme author's responsibility."
