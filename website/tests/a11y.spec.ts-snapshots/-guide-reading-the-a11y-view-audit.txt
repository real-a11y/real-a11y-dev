  heading "Interactive elements with no name" (level 3)
  paragraph "This is the single most common issue. An icon-only button, a link with no text, a form input with no visible label — these show up in the A11y view with a role but an empty name."
  button "Copy Code"

  paragraph
    text "A screen reader user hears:"
    emphasis ""button""
    text ". No context. They have to guess what it does, or give up."
  paragraph
    strong "The fix:"
    text "Add visible text, an"
    code "aria-label"
    text ", or link the element to a visible label with"
    code "aria-labelledby"
    text ". If the button has an icon, the icon needs an"
    code "alt"
    text "or"
    code "aria-label"
    text "."

  heading "Heading levels that jump" (level 3)
  paragraph
    text "Headings are how screen reader users navigate long pages — they Tab through headings the same way sighted users scan titles. If you jump from an"
    code "h1"
    text "directly to an"
    code "h3"
    text ", users navigating by heading lose their place in the hierarchy."

  heading "Images with no name" (level 3)
  paragraph
    text "An"
    code "<img>"
    text "without an"
    code "alt"
    text "attribute, or with"
    code "alt="""
    text "when the image conveys meaning, shows up in the A11y tree with no name. Decorative images should genuinely be decorative — if it communicates content (a product photo, a chart, a badge), it needs a description."
  heading "ARIA states that don't match reality" (level 3)
  paragraph
    text "An accordion"
    code "<button>"
    text "with"
    code "aria-expanded"
    text "is good. An"
    code "aria-expanded"
    text "that never changes when the accordion opens is a bug — the A11y tree will say "collapsed" while the panel is visually open. The A11y view will catch this: look at the state and ask whether it matches what you see on screen."
  paragraph
    code "aria-expanded"
    text "belongs on the control that opens something: a button, link, tab, combobox, menu item, tree item, row or grid cell. On a list box, a radio, a heading or a text field the browser ignores it, so the A11y view shows no state there. If a state you set doesn't show, move it to the trigger. A"
    code "<details>"
    text "has no state of its own either; its"
    code "<summary>"
    text "reports whether it is open."
  paragraph
    text "A button that opens a popover with"
    code "popovertarget"
    text "(or"
    code "commandfor"
    text "and a popover"
    code "command"
    text ") needs no"
    code "aria-expanded"
    text "at all: the browser reports it expanded while the popover shows and collapsed otherwise, and ignores an"
    code "aria-expanded"
    text "that says something else. The A11y view shows the browser's answer."
  heading "Elements that should be in the tree but aren't" (level 3)
  paragraph
    text "If a custom widget isn't showing up with the right role — or isn't showing up at all — it may be"
    code "aria-hidden"
    text ", visually hidden but also hidden from AT, or built with markup that doesn't carry semantic meaning. The A11y view makes absences visible."
