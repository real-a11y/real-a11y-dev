  heading "When to use it" (level 2)
  paragraph
    strong "Cross-referencing structure."
    text "The A11y view can feel abstract — a heading with no children, a landmark that swallowed half the page. The DOM view lets you trace back to the actual markup to understand why."
  paragraph
    strong "Spotting structural problems."
    text "Unnecessary wrapper"
    code "<div>"
    text "s, a"
    code "<button>"
    text "buried inside a"
    code "<table>"
    text ", an"
    code "<input>"
    text "sitting outside its"
    code "<form>"
    text "— structure issues are easiest to see here."
  paragraph
    strong "Checking what ARIA you actually applied."
    text "If you added"
    code "role="dialog""
    text "to a container but it's not behaving right, the DOM view will confirm whether the attribute landed where you think it did."

  heading "Semantic HTML vs. fake HTML" (level 3)
  paragraph
    text "There's a real difference between a"
    code "<button>"
    text "and a"
    code "<div role="button">"
    text ". Both show up in the DOM view. The"
    code "<button>"
    text "gets keyboard support, focus management, and correct announcement for free. The"
    code "<div>"
    text "gets none of that unless you wire it up manually."
  paragraph
    text "When you see custom elements ("
    code "<div>"
    text ","
    code "<span>"
    text ") carrying"
    code "role"
    text "attributes, that's a yellow flag — not necessarily wrong, but worth a second look in the A11y view to confirm the name and states are also correct."
