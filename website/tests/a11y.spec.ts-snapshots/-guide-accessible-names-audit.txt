  heading "Accessible Names" (level 1)
  paragraph
    text "The"
    strong "accessible name"
    text "is the string a screen reader announces for an element. It's what your user actually hears — and it's almost never just the element's text content. This page explains how that name is computed, what contributes, and what wins when multiple sources compete."

  heading "Spacing between a name's parts" (level 3)
  paragraph
    text "When a name is built from an element's content, each child that renders as a box of its own is separated with a space, and a child that flows inline is not — the same rule Chromium applies. So"
    code "<button><div>Save</div><div>now</div></button>"
    text "is"
    code ""Save now""
    text ", while"
    code "<button><span>Sa</span><span>ve</span></button>"
    text "is one word,"
    code ""Save""
    text ". A child that lends no text still separates the text around it if it renders:"
    code "<h1>Save<input>now</h1>"
    text "is"
    code ""Save now""
    text "."
  paragraph
    text "Text a child lends from an attribute is spaced off even when the child flows inline: an image's"
    code "alt"
    text ", a child's"
    code "aria-label"
    text ", a nested link's"
    code "aria-label"
    text ". So"
    code "<a href="/kb"><img alt="Help">center</a>"
    text "is"
    code ""Help center""
    text ", as in Chromium. The rule is about the child itself, not what lies inside it: a link whose only content is an image is still named by its content, so"
    code "<h2>Go to<a href="/"><img alt="Home"></a>now</h2>"
    text "is"
    code ""Go toHomenow""
    text "."
  paragraph
    text "Because the rule reads"
    strong "computed"
    code "display"
    text ", the same markup can produce a different name in jsdom than in a real browser wherever jsdom's CSS engine differs from a browser's. jsdom does not blockify flex or grid items, floats or absolutely positioned children, and it treats"
    code "<select>"
    text "and"
    code "<textarea>"
    text "as inline where a browser makes them"
    code "inline-block"
    text ". Those cases read as one word under a jsdom-based matcher and spaced in a browser. If a name looks glued only in jsdom, check the child's computed"
    code "display"
    text "before treating it as a bug — and prefer the Playwright path, which runs in a real browser, when the distinction matters to your assertion."
