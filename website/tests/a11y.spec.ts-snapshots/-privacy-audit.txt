  heading "Chrome extension — Semantic Navigator" (level 2)
  paragraph "The extension builds a semantic / accessibility tree of the page you're currently viewing and shows it in a side panel. It acts locally in your browser."
  paragraph
    text "It reads that tree from Chromium itself: Chromium's own accessibility tree, read over the"
    code "chrome.debugger"
    text "API (the same protocol DevTools uses), which includes what the page's DOM alone doesn't show, such as a media player's built-in controls. While the extension reads or acts on a page this way, Chrome itself shows its own bar across every window, reading “Semantic Navigator” started debugging this browser, independent of anything this extension displays. The first time this happens, the side panel shows a note explaining that bar."
  paragraph
    text "The side panel's TAB view, which lists the page's tab order, reads the page's DOM instead, and Chrome's bar doesn't appear for it. Where Chrome doesn't let the extension read a page over"
    code "chrome.debugger"
    text "(when DevTools is already open on it, for example), the side panel says why. Closing the last side panel lets go of the debugger."
  paragraph
    strong "What it does on the page:"
  list
    listitem "Reads the page's DOM (including iframes you can access): which frames the page shows, the text of its live regions, and, for the TAB view, its elements' roles, accessible names, states, and interaction info."
    listitem
      text "Reads Chromium's accessibility tree for the active tab over"
      code "chrome.debugger"
      text ", while it's attached."
    listitem
      text "On your explicit action (clicking a tree node's action button, pressing"
      code "Enter"
      text ", etc.), dispatches the corresponding event on the element — e.g. click a button, focus a field, submit a form."
    listitem "Draws a highlight overlay on the element under the cursor in the tree."
    listitem
      text "While the side panel is open, notices when you click, press"
      code "Enter"
      text "or"
      code "Space"
      text ", or type on the page, and tells the side panel only that you did, and when, never what you clicked or typed, or where, so the native tree can read what the page does next, and stop once you type."
  paragraph
    strong "What it does NOT do:"
  list
    listitem "It does not send page content, URLs, DOM snapshots, accessibility-tree data, or any other data to any external server — everything above stays local to your browser."
    listitem "It does not read from or write to the clipboard."
    listitem
      text "It does not use cookies, local storage, or IndexedDB for any personal data."
      code "chrome.storage.local"
      text "holds only the side panel's settings: whether names show in full, whether the tree follows page changes on its own, and whether you've dismissed the note about Chrome's debugging bar. While the debugger is attached,"
      code "chrome.storage.session"
      text "holds content-free bookkeeping about that attachment (which tab, since when), and while the screen curtain is on, which tabs it covers, so that closing the side panel still lifts it after Chrome has stopped the extension's background worker. Chrome clears both when the browser closes. No log of how you use the extension is kept."
    listitem "It does not track you across sites or sessions."
    listitem "It contains no analytics, telemetry, advertising, or third-party scripts."

  heading "npm packages" (level 2)
  paragraph
    text "The"
    code "@real-a11y-dev/inspector"

    text ","
    code "@real-a11y-dev/react"
    text ", and"
    code "@real-a11y-dev/storybook-addon"
    text "packages are pure libraries — as is the extraction engine bundled inside each of them. They:"
  list
    listitem "Run where you run them (browser, Node, jsdom, Playwright)."
    listitem "Make no network requests."
    listitem "Do not "phone home," collect usage data, or check for updates."
    listitem
      text "Have no side effects at install time beyond what"
      code "pnpm"
      text "/"
      code "npm"
      text "/"
      code "yarn"
      text "does normally."
  paragraph
    code "@real-a11y-dev/cli"
    text "and"
    code "@real-a11y-dev/mcp"
    text "build on those libraries but additionally drive a headless browser (Playwright) so they can audit a live page. That browser loads"
    strong "only the URL you give them"
    text "— the page you asked to audit — and reads its accessibility tree locally. They send no page content, no results, and no telemetry to us or any third party. Installing the browser with"
    code "npx playwright install"
    text "downloads it from Microsoft's Playwright CDN, the same as any Playwright project — that is the only network activity, and it is under your control. The CLI's"
    code "show-report"
    text "command serves your recorded test snapshots to your own browser, from a local server only your machine can reach."
  heading "Field values in what they print" (level 3)
  paragraph
    text "What these tools print is page content, and that includes what is"
    strong "in the page's form fields"
    text ". Their live output — the CLI's"
    code "tree"
    text ","
    code "tabs"
    text ","
    code "list"
    text ","
    code "inspect"
    text "and"
    code "interact"
    text "diff, the MCP server's tree, list, tab-order and diff tools — shows each field's value the way a screen reader announces it: the text in an email box, a chosen option, a draft in a rich-text editor. Wherever that output goes — your terminal, a CI log, or, for the MCP server, the AI agent you connected it to and that agent's model provider — those values go with it. Nothing is sent anywhere by the tools themselves."
  paragraph
    text "What they never print is a field the page marks as secret: a"
    code "type="password""
    text "field, or one whose"
    code "autocomplete"
    text "names a credential or a payment card ("

    text ","
    code "new-password"

    code "one-time-code"
    text ","
    code "cc-number"
    text ","
    code "cc-csc"
    text ","
    code "cc-exp"
    text ","
    code "cc-exp-month"
    text ","
    code "cc-exp-year"
    text "). Those read"
    code "[redacted]"
    text "— not the text, not its length. And the text you hand to a"
    code "type"
    text "command or the"
    code "type_text"
    text "tool is never echoed back."
  paragraph
    text "Outputs meant to be committed or shared — CLI"
    code "snapshot"
    text "artifacts and the diffs built from them, the MCP server's exported checkpoints — leave field values out unless you ask for them ("
    code "--values"
    text ", or"
    code "values: true"
    text "). That covers each field's own value; text the browser builds into an element's"
    emphasis "name"
    text "from what a field or rich-text editor holds (a heading typed into an editor, a button around a filled box) is part of the page's names and stays, except for sensitive fields. The strict mode below withholds that too."
  paragraph
    text "To keep every field value and all rich-text editor content out of the output, use the strict mode:"
    code "--redact-input"
    text "(or"
    code "defaults.redactInput"
    text "in"

    text ") for the CLI,"
    code "REAL_A11Y_REDACT_INPUT=1"
    text "for the MCP server,"
    code "attach(page, { redactInput: true })"
    text "in"
    code "@real-a11y-dev/testing"
    text "(with either tree). Use it when a page's ordinary fields may hold something sensitive the markup doesn't say is sensitive. The keyboard tab order (the CLI's"
    code "tabs"
    text ", the MCP server's"
    code "get_tab_order"
    text ") is built in the page rather than from Chromium's tree, and withholds the same way: no values, and a name that would carry typed text reads"
    code "[redacted]"
    text ". A link or button typed into a rich-text editor is not a Tab stop, so it never appears there; a"
    code "contenteditable="false""
    text "island such as a mention chip is one, and keeps its name."
