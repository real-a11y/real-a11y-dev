  heading "Mount <SemanticNavigator /> in a client component" (level 2)
    code "<SemanticNavigator />"
  paragraph
    text "Any component that renders the inspector must be a"
    strong "Client Component"
    text ". The inspector uses refs, DOM APIs, and (in floating mode) a portal to"
    code "document.body"
    text "— none of that is available during server rendering."
  button "Copy Code"
  code "// app/components/A11yPanel.tsx "use client"; import { useRef, type ReactNode } from "react"; import { SemanticNavigator } from "@real-a11y-dev/react"; export function A11yPanel({ children }: { children: ReactNode }) { const rootRef = useRef<HTMLDivElement>(null); return ( <div ref={rootRef} style={{ display: "contents" }}> {children} <SemanticNavigator root={rootRef} floating highlightOnHover /> </div> ); }"
  paragraph "Wrap your pages with it in the root layout, so the panel observes what they render:"
  button "Copy Code"
  code "// app/layout.tsx import type { ReactNode } from "react"; import { A11yPanel } from "./components/A11yPanel"; export default function RootLayout({ children }: { children: ReactNode }) { return ( <html lang="en"> <body> <A11yPanel>{children}</A11yPanel> </body> </html> ); }"
  paragraph
    code "root"
    text "is the element the panel observes: here, the"
    code "<div>"
    text "that holds your pages. It has to be attached to an element that holds them. A ref that never reaches an element, or one on an empty"
    code "<div>"
    text ", leaves the panel blank, and nothing is logged."
  paragraph
    text "The wrapper is"
    code "display: contents"
    text ", so it takes no part in layout: a flex or grid layout on"
    code "<body>"
    text "still lays out your pages' top-level elements as if they were its own children. A selector that names them as"
    code "<body>"
    text "'s children, such as"
    code "body > main"
    text ", no longer matches. Having no box of its own, the wrapper is the one row in the panel that hover can't highlight."
  paragraph
    text "The"
    code "floating"
    text "mode portals into"
    code "document.body"
    text ". The library already guards against SSR — the portal only activates after the first client commit — so you can render this component from a Server Component without a crash."
  heading "Gate it out of production" (level 2)
  paragraph "Two options — pick the one that matches your toolchain."
  heading "Option 1 — static gate (fully tree-shaken)" (level 3)
  button "Copy Code"
  code "// app/components/A11yPanel.tsx "use client"; import { useRef, type ReactNode } from "react"; import dynamic from "next/dynamic"; const SemanticNavigator = dynamic( () => import("@real-a11y-dev/react").then((m) => m.SemanticNavigator), { ssr: false }, ); export function A11yPanel({ children }: { children: ReactNode }) { const rootRef = useRef<HTMLDivElement>(null); // The wrapper renders in every build, so your pages sit in the same DOM in // development and production. In a production build the condition is // statically false: the panel never renders, and its chunk is never // requested. return ( <div ref={rootRef} style={{ display: "contents" }}> {children} {process.env.NODE_ENV === "development" && ( <SemanticNavigator root={rootRef} floating /> )} </div> ); }"
  paragraph
    text "Note:"
    code "dynamic(..., { ssr: false })"
    text "has to live"
    strong "inside a Client Component"
    text "in the App Router. Putting it in a Server Component throws a build-time error."
  heading "Option 2 — environment flag" (level 3)
  paragraph
    text "For staging deployments where you want to toggle the panel with an env var, use the component from Option 1 with this condition in place of its"
    code "NODE_ENV"
    text "check:"
  button "Copy Code"
  code "{process.env.NEXT_PUBLIC_A11Y === "1" && ( <SemanticNavigator root={rootRef} floating /> )}"
  paragraph "This ships the panel chunk in the production bundle as a separate chunk — it just doesn't run. Cheaper DX, more bytes."

  heading "Unit tests — Vitest + next-intl + Testing Library" (level 2)
  paragraph
    text "The App Router's"
    code "next-intl"
    text "navigation helpers ("
    code "Link"
    text ","
    code "usePathname"
    text ", etc.) read from the request-scoped intl context, which doesn't exist in a unit-test renderer. Mock them in"
    code "vitest.setup.tsx"
    text ":"
  button "Copy Code"
  code "// vitest.setup.tsx import "@testing-library/jest-dom/vitest"; import { afterEach, vi } from "vitest"; import { cleanup } from "@testing-library/react"; import type { AnchorHTMLAttributes, ReactNode } from "react"; afterEach(cleanup); vi.mock("@/i18n/navigation", () => ({ Link: ({ children, href, locale, ...rest }: AnchorHTMLAttributes<HTMLAnchorElement> & { href: string; locale?: string; children: ReactNode; }) => ( <a href={locale ? `/${locale}${href}` : href} {...rest}> {children} </a> ), usePathname: () => "/", useRouter: () => ({ push: vi.fn(), replace: vi.fn(), back: vi.fn(), forward: vi.fn(), refresh: vi.fn(), prefetch: vi.fn(), }), }));"
  paragraph
    text "Wire it into"
    code "vitest.config.ts"
    text ":"
  button "Copy Code"
  code "// vitest.config.ts import { defineConfig } from "vitest/config"; import react from "@vitejs/plugin-react"; import { fileURLToPath } from "node:url"; export default defineConfig({ plugins: [react()], resolve: { alias: { "@": fileURLToPath(new URL("./src", import.meta.url)) }, }, test: { environment: "jsdom", globals: true, setupFiles: ["./vitest.setup.tsx"], server: { // jest-dom ESM import needs this on Node strict resolution deps: { inline: ["@testing-library/jest-dom"] }, }, }, });"
