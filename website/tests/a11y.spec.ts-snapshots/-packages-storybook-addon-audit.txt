  heading "What changed" (level 3)
  paragraph
    text "The panel marks what each update of the story's tree changed, as the"
    link "inspector"
    text "does: open a menu in the story and the button that went expanded and the menu that came are marked, without hunting for them. A click or a key of yours on the story, or an action you run from the tree, is said to a screen reader with what it brought in the few seconds after it ("4 new, 1 changed in the tree"); typing in a field isn't read out at every key, and what the story changes on its own is marked without being said. A menu or toast the story mounts outside its root, at the end of"
    code "<body>"
    text ", is marked new on its own: the rest of the preview page the panel then reads isn't. A new story, the other mode ("
    strong "A11y"
    text "or"
    strong "DOM"
    text "), a reloaded canvas, and the panel shown again after another addon tab all start over, since nothing in between was compared. There is no checkpoint button in the addon. Turn the marks off with the"
    code "realA11y"
    link "story parameter"
    text "."

  heading "How it works" (level 2)
  paragraph "The addon follows Storybook's manager/preview split:"
  list
    listitem
      paragraph
        strong "Preview"
        text "("
        code "@real-a11y-dev/storybook-addon/preview"
        text ") runs inside the story iframe, as a project-level"
        code "beforeAll"
        text "annotation: Storybook runs it once when the preview starts, whichever way the addon reached the project's annotations (from"
        code "main.ts"
        text ", or named in"
        code "definePreview"
        text "). Extraction is"
        strong "lazy"
        text ": it only stands up a"
        code "DomObserver"
        text "(200ms debounce) after the manager emits"
        code "REQUEST_TREE"
        text "(panel open), and tears it down on"
        code "STOP_TREE"
        text "(panel hidden). While active it re-extracts on every debounced DOM mutation, but emits"
        code "TREE_UPDATED"
        text "over the Storybook channel"
        strong "only when that extraction differs from the last one it published"
        text "— so a mutation that extracts to an identical tree (an animation frame rewriting inline"
        code "style"
        text ", a change inside an"
        code "aria-hidden"
        text "subtree) costs no"
        code "postMessage"
        text "and no panel re-render at all. And because the observer only exists while the panel is open, animating or Controls-driven stories pay no extract and no"
        code "postMessage"
        text "cost at all while you're on another addon tab."
    listitem
      paragraph
        strong "Manager"
        text "("
        code "@real-a11y-dev/storybook-addon/manager"
        text ") runs in the Storybook UI shell (React). It asks for a tree only while its tab is selected and the addon panel is showing — read off its own box, since from Storybook 10.1 every addon panel stays mounted — subscribes to"
        code "TREE_UPDATED"
        text "events, deserializes the tree (the"
        code "[id, node][]"
        text "array back into a"
        code "Map"
        text "), re-applies the user's expand/collapse via"
        code "preserveExpandedState"
        text "(so a Controls tweak or animation does not snap open every row), and renders the interactive"
        code "TreePanel"
        text "from"
        code "@real-a11y-dev/semantic-navigator-ui"
        text "inside a shadow root."
  button "Copy Code"
  code "Preview iframe Manager (Storybook UI) ──────────────── ────────────────────── (idle until panel opens) Panel shown → REQUEST_TREE (mode) ←────────────────────────────────────────── start DomObserver + extract → TREE_UPDATED ───────── channel ─────────▶ deserialize tree (array → Map) { tree, mode, extractedAt } → render <TreePanel/> in a shadow root canvas reload → PREVIEW_READY ────────────▶ Panel still open → REQUEST_TREE (mode) ←────────────────────────────────────────── Panel hidden → STOP_TREE ←────────────────────────────────────────── stop DomObserver (no further extracts)"

  heading "Channel events" (level 2)
  paragraph "If you need to integrate with the addon from your own tooling:"
  button "Copy Code"
  code "import { EVENTS, type TreeUpdatePayload } from "@real-a11y-dev/storybook-addon"; // From Storybook 9 on, the channel APIs live on the `storybook` package: // `storybook/manager-api` in the UI shell, `storybook/preview-api` in the iframe. import { addons } from "storybook/manager-api"; // Preview → manager: // EVENTS.TREE_UPDATED — a fresh extraction (on every debounced DOM change that // altered the tree, while the panel is open) // EVENTS.PREVIEW_READY — preview iframe (re)booted; manager re-sends REQUEST_TREE if still open // EVENTS.USER_INPUT — what the user did on the story, while the panel is open: // "act" (a press or a key), "click", or "type" (typing in a field) // Manager → preview: // EVENTS.REQUEST_TREE — start observing, in the mode it carries, and send the current tree // (panel shown); a no-op while already observing in that mode // EVENTS.STOP_TREE — tear down the observer (panel hidden or unmounted) // EVENTS.SET_MODE — re-extract with a new view mode // EVENTS.HIGHLIGHT_NODE — highlight a node in the story by id // EVENTS.CLEAR_HIGHLIGHT — clear the highlight overlay // EVENTS.ACTIVATE_NODE — dispatch a node's primary action in the story const channel = addons.getChannel(); channel.on(EVENTS.TREE_UPDATED, (payload: TreeUpdatePayload) => { // payload.tree is a SerializableTree: { nodes: [id, node][], rootId } const { nodes, rootId } = payload.tree; console.log(rootId, `${nodes.length} nodes`); console.log(payload.mode); // "a11y" | "dom" | "tab" console.log(payload.extractedAt); // Date.now() timestamp // For the panel's change marks: the story root's own row, and the rows of the // preview page around the story an extraction widened for an overlay brings… console.log(payload.storyRows); // { rootId, outside: [id, …] } // …and false for a tree read after a story change, before the story rendered. console.log(payload.storyRendered); });"
  paragraph
    code "TREE_UPDATED"
    text "is de-duplicated: the preview compares each extraction against the last one it published ("
    code "mode"
    text ","
    code "storyRows"
    text "and"
    code "storyRendered"
    text "included,"
    code "extractedAt"
    text "excluded) and stays quiet when they are byte-identical. So it fires on"
    strong "changes to the extracted tree"
    text ", not on every mutation — do not use it as a DOM-mutation heartbeat, and do not expect a fresh"
    code "extractedAt"
    text "while a story is animating without semantic effect. The first publish after the panel opens and after a story renders is always sent, as is one whose"
    code "mode"
    text "differs from the last published — re-selecting the mode the panel is already in changes nothing and stays quiet like any other no-op."
  paragraph
    text "It is not a general mutation filter, though."
    code "class"
    text "is a key attribute and lands in"
    code "dom.attributes"
    text ", so a class toggle always publishes; and node ids are minted per DOM element, so a re-render that"
    strong "replaces"
    text "elements publishes even when the resulting markup is identical. Only a framework that patches nodes in place de-duplicates."

  heading "Panel features" (level 2)
  paragraph
    text "Inside every story's panel is the same tree as the inspector's, with the search, role filters and"
    link "keyboard"
    text "the Chrome extension's tree has too. Selecting or hovering a row outlines its element in the story canvas, without scrolling it, and activating a row runs its action in the story. Unlike the inspector's"
    code "highlightOnHover"
    text "and"
    code "scrollHostOnSelect"
    text ", none of this is configurable."
    strong "Show full names"
    text ", under ⚙ at the end of the toolbar, holds across stories until Storybook reloads. The addon has no Focus sync, scope breadcrumb or live region log."
