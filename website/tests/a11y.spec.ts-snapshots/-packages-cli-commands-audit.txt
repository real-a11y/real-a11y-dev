  heading "Socket and process isolation" (level 3)
  list
    listitem
      strong "Unix domain sockets"
      text "live under"
      code "~/.real-a11y/sessions/<name>/daemon.sock"
      text ", in a per-session directory created"
      code "0o700"
      text ". The socket file is created with"
      code "0o600"
      text "permissions, so only the owning user can connect — the kernel refuses other users at"
      code "connect()"
      text ", the same property a peer-credential ("
      code "SO_PEERCRED"
      text ") check would assert."
    listitem
      strong "Windows"
      text "uses a named pipe at"
      code "\\.\pipe\real-a11y-<id>"
      text ", where the id is random, stored in the per-user session directory, and independent of the per-session 256-bit auth token — pipe names are enumerable by every local process, so a name derived from the token would publish a hash of the secret. The real protection is the token, which lives inside the per-user session directory and is required for every RPC"
      code "auth"
      text "message. Node does not expose a way to set a restrictive pipe DACL, and"
      code "chmod"
      text "has no effect on Windows, so the CLI sets an explicit token-file ACL (via"
      code "icacls"
      text ") granting only the current user full control. This is fail-closed: if"
      code "icacls"
      text "is unavailable or the ACL cannot be applied, the session refuses to start — on the CLI side before spawning and again in the daemon before it reads the token — rather than leave the token relying on the profile directory's inherited ACL. Do not use"
      code "--session"
      text "with"
      link "--storage-state"
        code "--storage-state"
      text "on shared Windows machines, and keep"
      code "~/.real-a11y/sessions"
      text "inside a profile directory that is not readable by other users."
    listitem
      text "A"
      strong "pidfile"
      text "("
      code "daemon.pid"
      text ") records the daemon PID and version. A stale pidfile (daemon gone) or an incompatible daemon version is replaced on the next"
      code "--session"
      text "run, so a CLI upgrade does not silently talk to an old protocol."
    listitem
      text "Daemons exit automatically after the"
      link "--session-idle-timeout"
        code "--session-idle-timeout"
      text "elapses (default 15 minutes)."
      code "real-a11y session stop"
      text "and"
      code "real-a11y session stop-all"
      text "terminate them immediately and remove the session directory."
    listitem
      strong "The RPC trust boundary is the token, not the request contents."
      text "Any process that can read the per-session token file is the same OS user, and a request is treated exactly like that user running the CLI one-shot: it carries the caller's working directory, from which"
      code "a11y.config.json"
      text ", page lists, and relative"
      code "--output"
      text "paths resolve. The daemon grants nothing the caller could not already do directly; the working directory is pinned to the session's first run, so an existing session cannot be pointed at a different project directory."
