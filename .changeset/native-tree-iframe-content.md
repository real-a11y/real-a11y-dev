The native tree now reads the content of the page's iframes. It read only the top frame's document, so every `Iframe` row in `tree`, `audit`, `inspect`, `outline`, `snapshot`, the MCP tools and the testing package's native mode was empty: an embedded form, payment frame or widget was never printed or audited, and nothing said so. Each frame Chromium runs in the page's own process now sits under its `Iframe` row, one level deeper, as a screen reader reads it, and `audit` checks the controls inside it. Its fields follow the same value policy as the page's: a card number or password inside a payment frame reads `[redacted]`, and `--redact-input` / `redactInput` withholds every value. A finding inside a frame is located from the frame's own `<iframe>`, then `>>>`, then its path inside the frame (`#checkout >>> body > form > button`), so it never takes the fingerprint of one of the page's findings. `heading-order` and `landmark-structure` (and `assertHeadingOrder()` / `assertLandmarkStructure()`) judge the page's own document only, so an embedded widget's `<h1>` or `<main>` is not reported as a second one of the page's. On a session pinned to origins (`--storage-state` with its target and `--audit-origin`, `REAL_A11Y_MCP_ALLOWED_ORIGINS`), a frame whose document comes from any other origin is not read either, and its row stays empty: the pin checks the page's own URL, and the frame would carry the same cookies into the output. A `srcdoc`, `about:blank` or `data:` frame holds the page's own markup and is read. Not read yet: a frame Chromium runs in a process of its own — under site isolation, a cross-site or `sandbox`ed `<iframe>`, which includes the Chrome for Testing `real-a11y install` fetches and a Chrome reached over `--cdp` — whose row stays empty as before. Saved native snapshots and baselines of pages with iframes will churn: re-record them.
